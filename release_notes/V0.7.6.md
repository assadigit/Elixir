# V0.7.6 — The cleanup release: the test suite is honestly green, the repo is format-clean, the README tells the truth (and the cleanup found one real bug that had been hiding among the "rig failures")

> **What this is:** the maintenance release the post-campaign order called
> for: clear the known debt first (the 13 pre-existing test failures, the
> transcribe e2e's 5 standalone failures, the 9 format flags, the stale
> README badges) so everything after this runs against a clean tree.
> Every failure was diagnosed to its root cause before anything was
> touched — and that diagnosis found that **one of the "rig failures"
> was a real production bug that had been misfiled as noise.** Zero
> runtime behaviour change beyond that one disclosed fix.

## What you'll notice first

1. **The test suite is green — 9,262 passed, 0 failed** (9,196 in the
   full suite + 66 in the transcribe podcast e2e run standalone), for
   the first time since the badges were added. The README badge moved
   yellow → brightgreen with the real numbers.
2. **VibeVoice TTS works on source installs again.** It has been
   completely broken on source installs since V0.6.64 (October's
   Windows-installer release): the engine's helper process died at
   startup ("No module named 'utils'") and the engine then waited out
   its full 5-minute load timeout — every VibeVoice podcast attempt
   failed. Nobody noticed because the packaged Windows app fails soft
   by design, and the three tests that caught it were filed as "rig
   variance" in the V0.7.5 close-out. This release's cleanup diagnosed
   them properly and fixed the bug (a 3-line path bootstrap). The three
   tests pass with their original assertions **unchanged** — they were
   right all along.
3. **The repo is format-clean for the first time** — `ruff format
   --check` passes on all 917 files (the 9 pre-V0.6.83 stragglers are
   formatted; the diff is 45 insertions / 28 deletions, purely
   formatting), and `ruff check` stays clean.
