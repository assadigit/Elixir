## 2. "Never hardcode a specific TTS model" — now Rule 8, and already enforced

Your standing reminder: *never hardcode a specific TTS model, so an
incident like VibeVoice (now deprecated) doesn't happen again.* Two
things came of it:

- **The rule is recorded** as AGENTS.md Rule 8 — logic reads the
  configured setting, model paths stay single-sourced in Settings, the
  dropdowns are the designed place to list engines, and a dying engine
  must degrade to a clear message, never a break.
- **The sweep found exactly one violation, now fixed:** the wizard's
  start-of-conversion VRAM check assumed the TTS engine was NeuTTS no
  matter what you had configured. If you'd chosen Kokoro in Settings,
  the estimate billed NeuTTS's 1.5 GB instead of Kokoro's 0.5 GB —
  wrong advice from a hardcoded name, the same bug family as the
  translator mix-up (B7) fixed in V0.7.4. The check now reads the same
  setting the audio generator actually uses.

Four new tests pin the fixed behaviour (the hardcoded form can't come
back silently).

## 3. The audit's three tiny observations — the micro-cleanup batch

1. **The "Maximum" quality preset now explains itself.** Picking
   Maximum turns on self-consistency — an Ollama-only feature — and
   until now that caveat lived only on the checkbox the preset flips,
   so a non-Ollama user found out *after* choosing it. The preset
   dropdown now carries a tooltip naming exactly what each preset sets,
   including the Ollama-only / skipped-elsewhere / ~3-4× cost truth.
2. **The B3 phrasing in the campaign close-out is harmonized** — the
   open decision was never "whether any UI exposes it" (the Settings
   page has carried the checkbox since V0.4.19); it's whether any NEW
   surface (the wizard) should.
3. **`gap_fill_concepts` dropped its two dead parameters** — accepted
   for years, never read. Pure code hygiene; no behaviour change.
