## 1. The headline: the VRAM safety gate is dead code, and its 12 red tests were mispinned as "environment failures"

The V0.5.14 hotfix left an unconditional `return None` at
`core/pipeline/converter_impl.py:502` — the entire proceed/ask/abort policy block
after it (`:503-536`, 34 lines) is unreachable. The `local.vram_overbudget_policy`
setting (still registered), the `vram_overbudget_acknowledged` request field, and
the docstring (`:411-429`) that still promises ask/abort enforcement are all a
placebo. Consequence: 8 converter VRAM tests + 4 segmentation VRAM tests **fail at
HEAD** — and the last two session baselines listed exactly these 12 as "pinned
environment families." They are not environment failures; they are the test net
correctly screaming about a broken safety gate while the baseline notes myth-labeled
them. The audit's failure census (15 fails in this sandbox): 12 = this dead code,
2 = the contract conflict in §2, 1 = sandbox Qt (passes with full PySide6). The
decision the operator owes: restore the policy, or delete it honestly and update
the docstring + setting + 12 tests in one commit.

## 2. The two "environment" v182032 failures are a real contract conflict — reproduced deterministically

`test_run_post_checks_drops_confirmed_promotion` and
`test_garbage_set_dropped_legit_kept` fail with synthetic fixtures (no I/O). Root
cause: the V0.5.15 "regex-grounded exemption" (`postchecks/field_phases.py:482-501`)
keeps a bullet whose claimed author appears in `extract_citations` output — but a
parenthetical-only author ("(Khan 1983)") lands in that roster by construction, so
the exemption defeats exactly the misattribution drop the V18.20.3.2 veto was built
to enforce. The detector itself works (verified live: it returns the correct
claimed/real pair); the drop is what stopped firing. Needs an owner decision:
adopt the V0.5.15 contract in the tests, or tighten the exemption to
non-parenthetical presence only.

## 3. A second silent-routing bug: `dual_api` fast-provider override never applies

`conversion/summarization.py:793-798` overrides `_base_url`/`_api_key`/`_model` via
`hasattr` — but `OpenAICompatProvider` stores **public** `base_url`/`api_key`
(`openai_compat_provider.py:39-40`). The url/key overrides are silently skipped, so
a `dual_api` run sends concept extraction to the default cloud endpoint with the
default key and a foreign model name; the resulting error is swallowed as
"concept extraction unavailable" (`:960-963`). The model override is accidentally
compensated by the per-call `model=` argument. Queued with a characterization-test
requirement (the existing `test_fast_llm.py` covers a different, callback-injected
path).

## 4. Dependency drift on the RTL line

`arabic-reshaper` + `python-bidi` (the V0.6.5 RTL outputs) exist **only** in
`requirements.txt` — missing from `pyproject.toml [project.dependencies]` and from
`requirements.lock` (not regenerated when V0.6.5 added them). Two of the three
install surfaces silently lack them; the app degrades WARNING-only, so nobody
noticed. Queued: add to pyproject + regenerate the lock in one commit.
