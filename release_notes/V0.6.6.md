# V0.6.6 — the review-loop hardening: duplicate-heading data loss fixed (checkpoints + resume), stable Anki decks, crash-report trustworthiness, 49 new tests

The first release from the Agentic Review/Refactor/Test Loop charter (NEW_SESSION_PROMPT.md): two full review-fix-verify loops with independent fresh-eyes reviewers, every finding probe-verified before a fix and re-verified after. One release theme: **stop silent data loss and make the safety nets honest.**

## 1. The duplicate-heading family — silent summary loss (3 fixes, all probe-verified)

Any book with two chapters sharing a heading (two "Introduction" sections, repeated "Notes") hit a family of defects in the crash-safety machinery. Content-agnostic fixes — nothing book-specific.

- **The checkpoint collision (Loop 1):** the heading→position map collapsed both chapters onto ONE checkpoint filename — the second chapter's summary was silently LOST (the write-once guarantee skipped it), the first chapter was saved TWICE, and the second's per-chapter DOCX overwrote the first's. The map (`compute_final_positions`) now omits duplicated headings; colliding chapters fall back to their unique per-run index, which matches the end-of-run writer's numbering.
- **The resume-merge loss (Loop 2):** `merge_summaries` was heading-keyed — on resume with duplicate headings it dropped the loaded chapter's summary and emitted the new one twice, so the finished book's outputs were built without a completed chapter. The merge is now occurrence-aware (one summary per chapter, new-wins preserved for unique headings).
- **The manifest + DOCX collisions (Loop 2):** `chapter_manifest.json` was keyed by position number, which is not unique once duplicates fall back to per-run indexes — records clobbered each other. It is now keyed by the canonical summary filename (unique per chapter+run), with the position kept inside each record. **On-disk format change.** The per-chapter DOCX now carries the same run stamp as its markdown sibling, so a resumed run can never overwrite a completed chapter's DOCX — the "completed chapters are never touched" guarantee now actually holds.

## 2. Anki export — the deck that duplicated itself on every update

The deck/model ids were derived via Python's `hash()` under a "deterministic from book title" comment — but `hash()` is salted per process, so every Elixir run minted NEW ids for the same book (verified: 3 runs → 3 id pairs). Re-importing an updated `.apkg` therefore created a duplicate deck + duplicate notes instead of updating. Ids are now crc32-based — stable across runs and platforms. **Note:** the first import after this upgrade will create one final duplicate of each pre-V0.6.6 deck — delete the old deck in Anki once.

## 3. The release tool — three trustworthiness fixes

- `publish_release.py --all --zip` silently dropped the `--zip` (the `--all` loop never forwarded it) — a live run would have published every release with zero assets and exited 0. The combination is now rejected with a clear message.
- Transport failures (DNS, connection refused, proxy down) escaped as raw tracebacks; both the API helper and the asset upload now take the clean ❌ failure path.
- An unused binding left by the V0.6.5 upload fix (F841) had left the repo-wide ruff check gate red; both ruff gates (check + format, at the CI-pinned 0.16.8) are green again — 20 files re-formatted mechanically, and the `audit/` + `docs/ground_truth/` evidence trees are excluded from ruff's new markdown formatting so evidence artifacts can never be reformatted.

## 4. Test-suite integrity — the order-dependent failure is gone

The suite's own singletons leaked across tests: two V0.6.5 tests left an empty dict in the `Settings` DI slot (every later `Settings().get()` returned `None` — one test failed, others silently misconfigured); the shared `_runtime_state` reset only existed in one file, so pollution crossed file boundaries. Fixes: snapshot/restore at every override site, a session-wide autouse reset in `conftest.py`, and canaries that pin the clean state. The 15th (order-dependent) failure from the fresh environment is fixed — not hidden.

## 5. Crash reports — the redaction logic is finally tested

The code standing between a user-shared crash zip and their API keys had zero tests (it runs exactly when everything else is broken). 8 new tests pin the redaction variants (nested, case-insensitive, lists, empty values), the home-directory scrubbing, the end-to-end zip contents, and the never-raises path. Also fixed: a crash INSIDE a conversion produced a zip without the recent-log context — the controller's call site had drifted from main.py's V13.29.0 fix; both now share one `collect_recent_log_lines()` helper.

## 6. Zero-test features got their safety nets

- The multi-format input (EPUB/DOCX/TXT/MD/HTML — V10.20.0) had 0% coverage while wired into the live conversion route: 9 tests now pin routing, DOCX heading preservation, both stdlib fallbacks, and HTML script/style stripping.
- The Validation Tool's engine (89 statements) had 0% coverage: 11 tests pin load paths, keyword extraction (incl. the Persian branch), coverage math, hallucination flagging, and the report tiers.
- A 2013-era can't-fail test (`assert True`) guarding the VRAM-recovery log path now pins the actual delegation contract.
- The corrupted rebrand comment in `utils/settings.py` ("renamed Elixir → Elixir; ~/.elixir → ~/.elixir" — the real migration is `~/.markitdown_pro` → `~/.elixir`) now tells the truth.
