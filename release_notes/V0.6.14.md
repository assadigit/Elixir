# V0.6.14 — the single-model release: Fast Model and the whole fast/heavy dual-model concept REMOVED ("we only have ONE MODEL for LLM generation") — 7,622 P / 0 F

## The user report

> "Remove Fast Model and all of it code from the application... I
> previously might have used two LLM models for my tasks, but the results
> were not good. the idea failed... the concept of fast model and heavy
> model is obsolete. from now on we only have ONE MODEL for LLM
> generation. (not counting ocr, transcribe etc)."

The two-model architecture (a small "fast" model for simple tasks —
concept extraction, gap-fill, merging, scholar reflection — plus a
"heavy" model for deep work, alternating in VRAM) is retired. ONE model —
the summarisation model you pick, reached through your provider — does
every LLM generation task. OCR, transcription, translation, and TTS keep
their own dedicated models (the order's explicit exclusion). The
deletion is 82 files, +772/−2,788 lines.

## What was removed (everywhere: workflows, processes, functions, settings)

- **The request + settings schema:** `fast_model`, `heavy_model`,
  `model_architecture` (the 4-mode selector), `fast_model_temperature`,
  `fast_model_context`, `fast_api_url` / `fast_api_key` /
  `fast_api_model`, and `simplification_model` no longer exist. A
  load-time migration strips the stale keys from an existing
  settings.json (each logged once) so they don't linger or re-save.
- **The dispatch machinery:** `core/summarisation/fast_llm.py` (the
  4-mode router) deleted; `call_fast_ollama`; the Summarizer's
  `_call_fast_llm` / `_call_fast_ollama` / `_switch_to_fast_model` /
  `_switch_to_heavy_model`; the heavy-model coverage fallback (low
  coverage now relies on gap-fill + over-delivery + the 3-Tier
  Guarantee); the heavy-model "independent reviewer" branch (THE model
  reviews its own output — the merge logic still only lets it REMOVE
  unsupported claims); the simplification-model swap machinery (the
  simplified-keypoints digest uses THE model); the concept-extraction
  dual-mode branches (provider-routed: ollama/lmacpp/lmstudio → local,
  openai_compatible/claude → cloud).
- **The fast-model call sites:** gap-fill, batch gap-fill, scholar
  reflection, Tier-2 coverage gap-fill, and consolidation all call THE
  model directly. Behaviour note: Tier-2 gap-fill keeps the old
  router's sampling temperature (1.0), byte-identical to before — a
  fresh-eyes review caught this delta and it was pinned back.
- **VRAM + housekeeping:** the VRAM calculator's Fast/Simplification and
  Heavy entries (the budget now covers the ONE model per phase); the
  TOC heading labeler reads `summarisation.model`; `fast_api_key`
  retired from the keychain paths (a stale keychain entry is inert);
  `FAST_LLM_TIMEOUT_S` renamed `SHORT_LLM_TIMEOUT_S` (120 s, value
  byte-identical).
- **The UI:** the wizard's 4-mode "Model architecture" selector is
  replaced by a simple **"Where does the model run?"** choice — Local
  (Ollama / llama.cpp / LM Studio) or Cloud API — which writes only
  `summarisation.provider`. The fast-model dropdown, fast
  temperature/context parameters, the Fast API box + its Test button,
  the heavy-model and simplification-model pickers are all gone from
  the wizard AND Settings. The review/log screens no longer print
  Fast/Heavy/Simplification lines.

## What deliberately stays

- **The fusion provider** (local + cloud judging) — that is a *provider
  choice*, not a second model configured for generation.
- **B3 multi-sample voting** — sampling the SAME model several times,
  not a second model.
- **OCR / transcribe / translation / TTS models** — the order's explicit
  exclusion ("not counting ocr, transcribe etc").
- **Per-model temperature overrides** (`model_temperatures`) — tuning
  for THE model.

## Test path (what the operator will see on the rig)

1. Start your ONE model (llama.cpp or Ollama) → run a conversion: every
   task — sections, concept extraction, gap-fill, scholar reflection,
   self-review, the simplified keypoints digest, TOC heading labels,
   bullet consolidation — runs on that model. The wizard's Model step
   shows the simple Local/Cloud choice + the one model dropdown.
2. The conversion log no longer prints "Fast model: …, Heavy model: …".
3. Your existing settings.json: the retired keys are stripped on first
   load (one INFO line each: "retired the dual-model key …"); nothing
   else changes.
