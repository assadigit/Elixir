# V0.6.69 — no more "Ollama not running" error at startup. Instead: three little status lights in the top bar that watch your local LLM servers live — green the moment Ollama, llama.cpp, or LM Studio answers

## The report this ships

> "do not show the error of ollama when app loads. instead show a green
> light that shows whether ollama or any other locally famous LLM client
> is on or not, it must actively look for ollama or llama.cpp server as
> they're online and show a green light for them on ui instead"

Fair on all counts. The old startup behavior was a leftover from the
early days: if Ollama wasn't running when you opened Elixir, a modal
error dialog popped up before you had touched anything — and then stayed
wrong: start Ollama ten seconds later and the dialog's warning was
already stale. It also nagged even when you had never asked for Ollama
in the first place.

## What you get instead (in plain words)

**Three status lights live in the top bar**, one per local LLM server
Elixir knows how to talk to:

- **Ollama** (its usual home on `localhost:11434`)
- **llama.cpp server** (`llama-server` — checked on port 8080, and if
  that's quiet, on llama.cpp's newer defaults 8000 and 9931 — same port
  auto-detection the conversions already use)
- **LM Studio** (`localhost:1234`)

The rules are simple:

- **Green** — that server is running right now.
- **Gray** — it's not running. That's all. No dialog, no warning —
  a local server you haven't started is a perfectly normal state.
- **Amber** — for the first few seconds after the app opens, while the
  first check is still in flight.

**It actively looks.** The lights re-check every few seconds for as
long as Elixir is open. Start Ollama (or llama-server, or LM Studio) at
any time and its light flips to green within seconds — no restart, no
refresh, no clicking anything.

**Hover for details.** Each light's tooltip tells you exactly what the
check saw: "running · 7 models @ http://localhost:11434", or, when it's
gray, which ports were tried so you know what "not running" means.

**Small windows stay clean.** The lights are width-aware: on a wide or
maximized window each shows its name next to the dot; at the default
window size they shrink to compact dots (hover names them); on a very
small window they collapse to a single dot whose tooltip lists all
three. Whatever width you run at, nothing in the top bar gets squeezed
or clipped.

## Also in this release (under the hood)

- The check that feeds the lights runs entirely off the UI thread and
  can never freeze or crash the app — a broken probe just keeps the
  last known state and tries again on the next tick.
- It re-reads your configured server URLs when settings change (the
  lights follow the endpoints you configured, not just the defaults).
- The whole feature is pinned by 45 new automated tests, and the old
  startup-check tests were evolved to pin the new behavior instead.

## Upgrading

Install **Elixir-Setup-0.6.69.exe** from the Latest release (the
`V0.6.69-windows` tag) and just open the app — the lights appear in the
top bar and start watching immediately.
