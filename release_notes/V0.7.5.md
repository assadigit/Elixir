# V0.7.5 — The last two wizard steps stop over-promising: one honest "advanced" drawer, and a coverage number that finally means what it says (bug B4 closed by deletion; campaign complete)

> **What this is:** Phase ⑦ — the FINAL phase of the approved wizard
> rework (`ELIXIR_WIZARD_REWORK_ROUND_2_PLAN.md`, Steps 7-7b, work
> items 7a-7d). The V0.7.0-V0.7.4 releases rebuilt the shell, Step 1,
> Steps 2-3, Step 4, Step 5, and Step 6; this release reworks the last
> two steps and, with them, closes the campaign: every finding in the
> Round-1 audit is now fixed, deleted, or honestly documented.

## What you'll notice first

1. **Step 7 is one choice plus a drawer.** The step is now just
   "Split strategy: Auto" with an honest explanation underneath — the
   full order the app really tries (the book's own chapter outline →
   table of contents → fuzzy TOC → headings → semantic → page-group
   blocks → fixed tokens → the whole document as one section), with
   semantic's cost named plainly: one extra AI call that samples the
   first ~3,500 tokens. Everything else lives behind a "Show advanced
   settings" toggle: the token limit (Auto — the default 2,000 — or
   manual), and the semantic-fallback switch. The manual token field
   only enables when the Token strategy is actually in play, because
   that is the only place the number is ever read.
2. **Three controls are gone because they lied or did nothing.** The
   "Academic rigor (temperature=0)" checkbox (temperature 0 hasn't
   happened for a long time — the real mechanism, auto-enabling for
   academic papers, stays in the engine); the "Conservative drop mode"
   checkbox (a debugging stance — the engine and the quarantine panel
   keep it); and the token-budget slider — the last live bug in the
   audit (B4): its Step-4 sync could never fire (it looked for a
   `step4` attribute on the Step-7 widget), Step-4's save clobbered
   whatever it wrote, and its presets force outputs on that this
   campaign removed from the wizard entirely. Deleting it closes B4.
3. **The coverage number finally means what it says.** This is the
   release's biggest honesty fix. Before: you set 85% and the pipeline
   chased a hidden 100% target, accepted anything above ~76% with only
   a warning, and no regeneration ever closed the gap. Now: your
   threshold is THE target. The pipeline measures real coverage, and
   if it lands below target − 3, it regenerates the *missing* bits
   (targeted gap-fill, the same machinery that was already there),
   re-measures, and tries up to 3 rounds. Then it tells you the truth:
   "Coverage 87% — target met", or "Reached 83% after 3 attempts;
   remaining gaps: …". Step 7b's spin now reads "Coverage target:" with
   the caption "Regenerates until measured coverage reaches this level
   — ±3 for model randomness, max 3 rounds."
4. **Self-consistency moved out of the wizard and stopped
   over-promising.** The checkbox said "multi-sample voting — slower,
   more accurate". The truth (now the label, in Settings → AI
   quality): it only runs on Ollama — on every other provider it was
   silently skipped, and now a warning says so; it costs ~3-4×; and
   the "vote" is a union-merge of sample agreement, not a majority
   vote. Default off, as before. The engine itself is untouched.
5. **A "Use recommended settings" button on the Fine-tuning step.** In
   one click it applies the audited defaults for that step: Coverage
   85 · resume on · cache off · content filter on · clean markdown and
   page-heading removal on · DOCX with TOC (author Elixir) · the
   embedding and performance knobs at their audited values. The
   tooltip is honest about what it does NOT touch: self-consistency
   (Settings-owned, off by default) and the model limits (Step 5,
   Auto by default).

## How it works

**7a — the advanced disclosure.** The honest strategy copy is pinned
to the code it describes: a test parses the real AUTO cascade out of
`segmenter.py` and fails if the UI copy's stage list ever drifts. The
token-limit gate is wired live — the manual field enables only under
the Token strategy (its single consumer, `TokenSegmenter`); under
every other strategy the limit is never read, and the note under the
field says so. Deleting the slider took its dead Step-4 sync and the
presets (whose "Thorough" position force-enabled the deprecated
outputs) with it. The wizard state no longer carries academic-rigor
or conservative-drops — so a value you set in Settings now survives a
wizard run instead of being quietly forced back to off.

**7c — the coverage loop.** One target: the engine's "effective
target" is now simply your threshold (the over-delivery domination is
gone; the old best-effort acceptance floor went with it). The new
loop (`core/summarisation/coverage_loop.py`) is deliberately the same
machinery, repeated with a cost bound: the missing-concept list comes
from the runtime keyword extractor only (content-agnostic — it works
the same on any book), each round caps at the existing 12-concept
trim, the insertion path keeps the Tier-2 quality guards (thinking
filter + near-duplicate), and the terminal report names what is still
missing. If you set an impossible target, you get "Reached X% after 3
attempts" — never a silent best-effort acceptance.

**The golden fixtures were re-frozen in the same commit** (the
release-gate procedure), which also resolved this rig's three
long-standing stale golden/eval failures: the scorecards are
identical before/after (the loop no-ops in-band, so pipeline outputs
are byte-identical) — what changed was the prompt-manifest hash,
which had been stale since an earlier session's transcribe-prompt
edit.

  reworked steps.
