## The fresh-eyes review (two parallel read-only reviewers, pre-release)

Both verdicts: **RELEASE READY** — and every SHOULD-FIX was fixed
BEFORE shipping, each with a pin:

- **The 416 dead end:** a `.part` at-or-beyond the remote's size
  (remote shrunk, or a cancel between the last chunk write and the
  rename) re-sent the same unsatisfiable Range forever. Now: a 416
  probes the fresh size — equal to the .part means "already
  complete" (finalized with ZERO bytes moved); anything else means the
  remote changed (one clean restart from zero).
- **The corrupt-mix path:** a blind Range resume against a
  REPUBLISHED remote welds the stale prefix to the fresh suffix — a
  file that passes the size check AND the header check (the review
  proved it dynamically). Now the resume is only trusted when the
  `.part` carries its ETag sidecar AND the server honors `If-Range`
  (a 206); anything else restarts from zero. The sidecar is written
  BEFORE the first body byte, deleted with the rename.
- **Close/Esc didn't cancel:** only the window X reached closeEvent —
  now `reject()` (Close button + Esc) carries the same cancel policy;
  the .part survives either way.
- **The env-dependent test + the unpinned POSIX guard:** the exe-models
  fallback test consulted the real `$HOME`; the last-resort test
  monkeypatched past the very guard it meant to pin. Both fixed — the
  guard now has its own chdir test (the literal `C:\transcribe.cpp`
  folder once actually appeared in the repo CWD this session; it is
  now impossible and pinned).
- Plus: the stale progress-line on failure/cancel, the "use existing"
  path, the URL-filename traversal pins (`..` is a REAL pathlib
  component — caught explicitly), the `.en`-variant Language line in
  the tooltip, and three weak pins (a tautology, a subsumed disjunct,
  a dead monkeypatch) tightened.

## The rig flow after V0.6.60

Open the Transcribe Service dialog → the GGUF row's "⬇ Get models" →
the catalog lists handy-computer's files (★ turbo Q5_K_M first) →
Download → live progress → "✅ downloaded and verified — selected in
the GGUF dropdown" → Transcribe. A cancelled download resumes where
it stopped (even across app restarts — the `.part` + its ETag sidecar
stay on disk). A model that already exists is offered for reuse
through the same verification gate. Nothing leaves the app: no
browser, no manual folder picks, no "where did it download to".

## Remaining boundary (honest)

Sandbox-only: no PySide6 — the two dialogs' wiring is AST-pinned, the
leaf behaviorally tested; the rig's first "⬇ Get models" click is the
final visual check. Accepted risk: a server that lies about
Content-Length on the FINAL chunk is caught by the size sanity check
(.part kept); a deliberately adversarial server that serves correct
sizes but wrong bytes is out of scope (the GGUF-header verification
still gates what gets installed). The full-file sha256 cross-check
(the HF API exposes the xet hash) is a future nicety — the header
check + size check + ETag resume cover the realistic failure modes.
