# V0.6.55 — the Transcribe Service fundamental redesign (the video → transcribe → summarize chain: llama.cpp port auto-detection 8080/8000/9931, the CPU-fallback speed probe + 🔌 Test button, the 8000-char amputation killed, ONE round trip for notes+tutorial, live streaming to the status label, structured TranscribeError family, parser edge cases) — 119 new pins / 548 P sweep / 0 regressions

## The user report

> "The transcriber tool is supposed to transcribe using whisper to raw
> text (which takes 30-40 seconds) then give that text to llm model for
> summarize and tutorial, but it doesn't happen."

Annotated with a screenshot of a `llama-server` console on
`http://127.0.0.1:8000` showing the `n_gpu_layers=99` GPU-fit warning
(the 27B model did not fit in VRAM; the server fell back to CPU and
still listens). The redesign mandate: six prioritized items (P1-P6),
each fixed with a test that fails on the pre-fix code and passes on
the post-fix code (the stash/pop verification bar).

## P1 (URGENT) — the llama.cpp port trap + the invisible CPU fallback + the Test button

**The port auto-detection.** The app's single hard default was
`http://127.0.0.1:8080/v1`; the rig's llama-server listens on **8000**
(llama.cpp's current default — its own console prints "server default
port will be changed to :9931 in a future release"). Every
llama.cpp-first routing decision therefore probed a DEAD port and fell
back to Ollama. Now: when the configured URL is the UNMODIFIED default
and dead, the well-known alternates are probed in order (8080 → 8000 →
9931) — first LIVE port wins, in `decide_llamacpp_first` (the routing)
AND `create_provider`'s llamacpp branch (the factory, via the shared
`resolve_llamacpp_base_url`) so the provider actually TALKS to the
detected server. An explicit operator-configured URL is never
second-guessed (the V0.6.12 deliberate-choice contract). The probe
cache bounds the cost; the routing note says the port was
auto-detected.

**The generation-speed probe (the CPU-fallback detector).** The app
can never read the server's console — but llama-server that failed to
fit its model in VRAM still ANSWERS, just 10-30x slower (a 27B on CPU
generates ~1-2 tok/s vs 20-100+ on GPU). `probe_llamacpp_generation()`
runs a 16-token timed generation through the REAL streaming path and
classifies the rate; below 5 tok/s the verdict is
`slow-cpu-fallback-suspected` and the message names VRAM /
`n_gpu_layers` / the CPU fallback and the fix (restart llama-server
with a lower `--n-gpu-layers`, e.g. `-ngl 40`, or a smaller quant) —
the actionable version of the console warning.

**The 🔌 Test button** (the Transcribe dialog's LLM row): one click
resolves the backend (both llama.cpp port families + Ollama), probes a
real tiny generation, measures its speed, and renders the verdict —
healthy (info box) / CPU-fallback suspicion (warning, the n_gpu_layers
guidance) / unreachable (critical, with the start-your-LLM fix). It
runs on a worker thread (never blocks the UI) and persists an
auto-detected port to settings after TELLING the operator (one click
fixes every future run).

## P2 — the 8000-char amputation killed

`summarize_transcript` sliced `transcript[:8000]` before rendering the
prompt — a 15-min video (~15-20k chars) lost roughly HALF its
transcript silently. Now `fit_transcript_to_budget()` fits the
transcript into a 24k-token prompt budget (the whole 15-min video
passes; only an absurd 3h+ wall trips the cut) — and when it does cut,
it cuts on a sentence boundary (word boundary as the last resort),
appends an explicit `[... transcript truncated: X of Y characters …]`
marker (its tokens reserved in the fit — body+marker never exceed the
budget, the Task 9 review fix), and logs the cut at WARNING level. The
silent amputation class is dead: the wiring pin feeds a 20k-char
transcript and asserts the TAIL reaches the prompt (fails on the
pre-fix code).

## P3 — ONE round trip for notes + tutorial

Both outputs used to run TWO sequential full LLM generations over the
same transcript (2x the wall-clock at 2-6 tok/s). Now
`summarize_transcript_combined()` renders one combined prompt
(`prompts/transcribe/transcript_combined.md`) that asks for both
documents separated by an exact marker
(`<<<ELIXIR-TRANSCRIBE-SPLIT>>>`), makes ONE provider call, and splits
the response with a drift-tolerant splitter (case, 1-6 angle brackets,
hyphens/underscores/spaces, stray code fences, own-line markers
preferred over inline mentions). If the model ignores the marker, the
service signals `split_ok=False` and the dialog falls back to the
separate tutorial call — correctness is never sacrificed to save a
round trip.

## P4 — the LLM output streams to the UI

`on_chunk=None` meant a frozen "Summarizing with LLM..." label for
10+ minutes on the rig. Now every LLM call forwards the caller's
`on_chunk` (the provider already throttles to 2 emissions/s) and the
dialog's callback shows the generation growing:
"📝 LLM is writing… 1,234 chars so far". A healthy slow generation and
a hang are now distinguishable at a glance.

## P5 — the structured TranscribeError family

The V0.6.53 NameError (one typo → raw traceback to the operator, raw
transcript saved, no summary) was the fragility signal.
`core/transcribe/errors.py` defines the family — `TranscribeError`
base with `stage` / `message` / `hint` (str(err) IS the user message:
stage + what + fix) + `AudioExtractionError`, `EngineNotFoundError`,
`TranscriptionEngineError`, `EmptyTranscriptError`,
`LLMConnectionError`, `LLMEmptyResponseError`, `LLMGenerationError`,
`TranscribePipelineError`. The service raises them (timeout /
connection / generation mapping; a None provider return — the REAL
failure mode after the providers' internal retries give up — is a
CONNECTION error with the start-your-LLM hint, the Task 9 review fix);
the dialog catches `TranscribeError` and wraps anything unexpected as
`TranscribePipelineError` (traceback to the log, friendly message to
the user). The V0.6.53 failure class can never reach the operator raw
again.

## P6 — the transcribe.cpp parser edge cases

Each was a silent transcript DROP: `-->` arrows (whisper.cpp dialect)
and `HH:MM:SS.mmm` / `MM:SS.mmm` stamps now parse as segments;
wrapped `text:` continuation lines are kept (info prefixes and
timestamp lines end the block; the block never crosses the
stdout/stderr boundary — the Task 9 review fix); a segments-only
output builds its text from the segments (not the raw-stdout
fallback); `detected language:` (space) recognized; a UTF-8 BOM is
stripped; percent-bar progress lines are skipped. The V0.6.52
real-format regression floor is pinned.

## The fresh-eyes review (Task 9) — one BLOCKER caught and fixed

The independent read-only review found the initial
`_on_engine_changed()` call was placed BEFORE the whisper widgets
existed — an AttributeError on dialog construction on any real PySide6
install (the exact V0.6.53 failure class, invisible to this sandbox's
PySide6-less suite). Fixed (call moved below the widget creation) +
pinned permanently (a construction-order AST pin). Three SHOULD-FIX
defects fixed in the same pass: the parser's stderr pollution across
the stream boundary, the budget marker overflow (24,036 tokens for a
24,000 budget — measured), and the None-return misclassification.

## Behavior notes (deliberate, documented)

- The dialog's engine combo now DEFAULTS to transcribe.cpp (matching
  the service default since V0.6.42 and the operator's Vulkan rig) —
  the dialog default and the service default had silently disagreed.
- When both LLM outputs are checked, ONE combined failure aborts both
  (the old flow still attempted the tutorial after a dead summary —
  a second doomed round trip); the raw transcript is still saved, so
  the failure stays non-fatal to it.
- Two STALE pins were updated as documented contract changes (house
  Rule 4): the V0.6.12 all-dead probe count (1 → 3) and the V0.6.54
  summarize call-site count (2 → 4: 1 combined + 3 single). The
  load-bearing guarantees are preserved and extended.
- The v0600 empty-response pin now asserts the structured raise (the
  old "Error:" string contract is gone), and the v0600 default-engine
  pins were refreshed to the V0.6.42+ transcribe_cpp default.
