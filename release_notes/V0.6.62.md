# V0.6.62 — "and now put it back in the video": the subtitle export (SRT + WebVTT) — the engine's timestamped segments become the one deliverable video tools actually consume — `<video-name>.srt` (VLC, every editor, YouTube) and `.vtt` (HTML5/web players) written beside the transcript, with a rich-text completion dialog (a proper files table: icon + bold name + per-file description, the subtitle rows carrying the cue count) — 62 new pins / 556 P affected sweep / 0 regressions

## The gap this closes

> The V0.6.61 stage summary: "the transcribe tool's model arc
> (V0.6.53 crash → V0.6.54-58 UX/telemetry → V0.6.59 catalog →
> V0.6.60 downloader → V0.6.61 off-thread + integrity) is COMPLETE
> end-to-end on the code side… the next natural focus moves to the
> NEXT tool or the broader app."

The model story being done exposed the OUTPUT story: the app that
transcribes VIDEO could write `transcript.md` / `summary.md` /
`tutorial.md` — and nothing else. The engine has parsed timestamped
segments (`{"start": float, "end": float, "text": str}`) since the
V0.6.55 P6 parser work, but those timestamps ended at the markdown
file's `[MM:SS.ss]` prefixes. The one deliverable every video
player, editor, and platform actually consumes — a subtitle file —
did not exist. This release makes the transcribe tool round-trip:
video in, subtitles out, one click.

## The release — three pieces

1. **THE LEAF (`core/transcribe/subtitle_export.py`, Qt-free,
   stdlib-only):** `format_srt_timestamp` (`HH:MM:SS,mmm` — the
   comma standard; hours widen past 99; negatives/non-finite clamp
   to zero; half-up rounding that is PINNED, because the
   `seconds*1000` product CAN land exactly on k+0.5 — `0.0025 *
   1000.0 == 2.5` exactly — where Python's `round()` would go to
   even) and `format_vtt_timestamp` (`HH:MM:SS.mmm` — the dot
   standard). `wrap_cue_text`: the broadcast-standard 2×42-char
   cue — greedy word wrap, over-long words hard-split, and WORDS
   ARE NEVER DROPPED (content that does not fit merges into the
   last line, which may exceed 42: honest over pretty; for a
   transcript, missing words are worse than a long line). Cue
   hygiene: empty-text segments skipped with CONTIGUOUS numbering,
   inverted timestamps (end < start) clamped to zero length, a
   stray `-->` inside cue text sanitized to `-›` (it is the SRT
   structure delimiter — a transcript line like "drag a --> b" must
   never forge a phantom timing line), `\r` normalized, and the
   wrap=False path folds interior blank lines (a blank line
   TERMINATES a cue — the block would split in two). The
   writer `write_subtitle_files`: `<stem>.srt` + `<stem>.vtt`, no
   segments → `cues: 0` and NO file (an empty .srt is a broken
   deliverable), hostile stems contained (`Path(file_stem).name`;
   empty/all-dots rejected — the V0.6.60 traversal-precedent
   class), OSError/ValueError/TypeError → the `error` key, NEVER a
   raise (the transcription already succeeded; a bad output folder
   must not retro-fail the run), idempotent replace, both-formats-
   off → not even a directory created.

2. **THE WIRING (transcribe dialog):** a 🎬 subtitle checkbox row —
   `Subtitles (.srt)` default ON (the natural companion of the raw
   transcript) + `.vtt (web)` opt-in, tooltips that say what each
   format is FOR. `save_srt`/`save_vtt` ride the options dict and
   the run header (a `🎬 Subtitles: SRT + VTT` line in the live
   log). Step 3b in `_do_transcribe` writes the subtitles from the
   engine's own segments AFTER the raw save and BEFORE every LLM
   call — the V0.6.54 contract extended: an LLM failure (the slow
   rig's 10-minute frozen-summary failure mode) never costs the
   subtitles, exactly like the raw transcript. No segments (the
   segments-as-text fallback) → an honest "⚠️ No timestamped
   segments — subtitles skipped" log line, no broken file. A
   subtitle write failure surfaces as `results["subtitle_error"]`
   → a ⚠️ status part + its own completion-box row.

3. **THE COMPLETION DIALOG (the styling upgrade):** the plain
   name-list message box is now RICH TEXT — an HTML files table
   (icon + bold escaped file name + muted italic per-file
   description; the subtitle rows carry the cue count; error and
   output-folder rows), `html.escape` on every interpolated
   string, and the call SHAPE unchanged (`QMessageBox.information`
   + the "✅ Transcription Complete" title) so the rig e2e
   message-recorder contract is preserved. The stale early-critical
   branch is fixed too: it keyed ONLY on `raw_path` — with save_raw
   off + 🎬 on + an LLM error, the user got a bare "❌ Failed" that
   HID the .srt/.vtt that did land; it now honors every on-disk
   deliverable and shows the completion box with the error as a ⚠️
   row.

## The fresh-eyes review (two parallel read-only reviewers) ran pre-release: both RELEASE READY, and every SHOULD-FIX was fixed BEFORE shipping, each with a pin

- The `wrap_cue_text` infinite loop on `max_chars <= 0` (an 8s+
  hang proved dynamically) → params clamped at entry, pinned.
- The `file_stem` traversal (`"../escape"` wrote OUTSIDE dest,
  proved) → `Path(file_stem).name` + empty/all-dots rejection,
  pinned (containment + rejection both).
- The never-exact-half-ms docstring claim was FALSE (`0.0025 *
  1000.0 == 2.5` exactly — the float error cancels; `round()` would
  differ) → the note reworded to "the half-up choice is
  load-bearing" and the boundary PINNED (`0.0025 →
  00:00:00,003`).
- The subsumed-substring weak pin (`"🎬 Subtitles: SRT"` ⊂ `"🎬
  Subtitles: SRT + VTT"` — a save_vtt-ignoring implementation
  passed, proved) → exact line equality.
- The stale early-critical branch (above) → the any-deliverable
  condition + AST pin.
- The vacuous addStretch row pin (a mutant splitting the pair onto
  two full-width rows survived every pin, proved) → a STRUCTURAL
  pin: some single `_HL()` row must receive BOTH checkboxes AND a
  stretch.
- The unpinned `html.escape` property (stripping all three escapes
  survived every pin, proved) → the exact call sites pinned.
- The subtitle-error-only-in-the-log gap → `results["subtitle_error"]`
  + status part + box row, pinned.
- NICEs also shipped: `wrap=False` blank-line folding, the
  both-off no-mkdir guarantee, ValueError/TypeError in the
  never-raise net, `subtitle_stats` end = max() not last (unsorted
  input cannot under-report), `wrap_cue_text(None) → ""`, the
  generator re-iterability doc note, `subtitle_cues`' 0-init
  pinned.
