# V0.7.4 — Step 6 stops hiding that translation is optional, follows your Step-4 picks, and tells the truth about the harakat file and the VRAM bill (bugs B7 closed)

> **What this is:** Phase ⑥ of the approved wizard rework
> (`ELIXIR_WIZARD_REWORK_ROUND_2_PLAN.md` — Step 6, work items
> 6a-6c). The V0.7.0-V0.7.3 releases rebuilt the wizard shell,
> Step 1's mode cards, Steps 2-3, Step 4's category cards, and
> Step 5's model listing; this release reworks the translation step —
> the one that decides whether and what gets translated after the
> conversion — and closes the audit's B7.

## What you'll notice first

1. **Translation says it's optional, out loud.** The step now opens
   with a master **"Translate outputs"** switch and, right under it,
   the caption **"Optional — runs after conversion."** Before this
   release the only hint that you could skip the step was an
   unchecked checkbox — no tooltip, no "optional" copy (audit §W10).
   Everything below the switch greys out when it's off.
2. **"Translate the outputs I selected in step 4" — and mean it.**
   "What to translate" is now a radio with two modes (D15):
   **"The outputs I selected in step 4"** (the default) or
   **"Let me choose"** (the old 11-checkbox list, now hidden unless
   you pick it). In the default mode you never re-tick a dozen boxes
   here: at Start, the wizard derives the translation list from your
   Step-4 selection through a new registry-driven mapping — the same
   single source of truth that drives the Review and the start-log.
   The whole-book translation (`Full book Markdown`) is never derived
   — it stays an explicit manual tick, because it is by far the most
   expensive translation job. The Review step and the start-log say
   exactly what will happen: "follows Step 4 — Chapter summaries,
   Keypoints" (or your manual list, in the other mode).
3. **The model boxes are real and they remember.** The Harakat and
   Judge model pickers open on your last-used picks (the V0.7.3
   "manual picking, auto-remembered" pattern), list the server's
   models off the UI thread (the old code made a blocking HTTP call
   while building the page — a hung server froze the wizard open for
   up to 5 seconds), and a **Refresh models** button re-lists. A pick
   the server no longer lists stays selectable. The empty case is a
   quiet hint line, never a pop-up.
4. **The `.harakat.md` file stops pretending.** Every surface now
   says the truth: the diacritized Farsi copy is a **manual-review
   file** — nothing downstream reads it yet, and the Podcast-Maker /
   TTS wiring is on the backlog (D16). The Settings page's
   "automatically used when generating Farsi podcast audio" claim,
   the module docstring's "feeds directly into the Podcast Maker",
   and the file-map's "TTS-ready" comments are gone.
5. **The VRAM warning finally bills the right model.** Before a run
   starts, the VRAM estimate used to pass the *summarisation* model
   as the translator (audit B7) — so the translation phase's number
   was for the wrong model entirely (a 27B summariser instead of the
   4B/12B TranslateGemma that actually loads, or vice versa). The
   check now reads the real translator — the same `translation.model`
   setting the translation service itself uses — and agrees with the
   converter-side re-check.

## Two dead settings keys deleted

`translation.outputs.packets` (no backend file-glob ever read it —
the key never selected anything) and
`translation.harakat_confident_only` (never read by any backend; the
confidence-first behaviour lives in the prompt itself, not a setting)
are purged: a fresh install never sees them, and a legacy
`settings.json` carrying them gets them removed on load (the same
migration pattern as the old NLLB key). The Settings page's dead
"Confidence-first" checkbox is gone with its key.

## The mapping — why the two lists can't drift

The new derivation lives in the outputs registry, next to the
function that enumerates your selected outputs: a table maps each
translation key to the Step-4 selections that turn it on
(exec + thorough → chapter summaries, keypoints → keypoints, and so
on). Pin tests assert the table's keys are exactly the backend's real
file-glob keys and that its labels match the Settings page's manual
list — add a translatable output in one place and the pins fail until
the other follows. Deprecated outputs never map; the summaries family
only counts while the summaries master switch is on; and a mode-A
Start rewrites the whole selection, so nothing stale survives from a
previous manual choice.

- The translation backend itself — TranslateGemma via Ollama, the
  validation judge, the glossary machinery, the 30-minute freshness
  filter: all untouched (translation is a settings-driven
  post-conversion phase; the mode-A work is a mapping layer in front
  of it).
- The B1/B5 protections from the V0.6.86 hotfix — the empty-selection
  guard and the load-then-save round-trip are pinned and re-tested on
  the reworked step.
- The Settings translation page's structure (minus the one dead
  checkbox and the honest copy); its manual output list remains the
  mode-B surface.
- Steps 7-7b functionally — phase ⑦ (the FINAL phase: advanced
  disclosure, self-consistency relocation, coverage honesty,
  fine-tune defaults, B4 by deletion) is next at V0.7.5.
