# V0.6.83 — UI/UX correction Round 3: the properly sized window (1440×900 first-run target, screen-derived 1100×720 minimum, implausibly-small restores clamped up), the responsive sidebar rail (clamp(180, 0.18·w, 260), compact profile with word-wrapped nav labels), the body-driven hero (~0.325 of the viewport with a fully scalable text rhythm and the still-life as a TRUE transparent RGBA composite), and the tiered Quick Tools reflow (measured single-line comfort gate above the readability floor)

> **The correction spec behind this release:** the Round-3 audit
> (`ELIXIR_UI_UX_CORRECTION_ROUND_3.md`) measured the shipped dashboard
> against the approved reference and found the primary defect was the
> WINDOW: a ~893×609-class geometry with a ~30% sidebar could only ever
> compose one clipped card column. This pass fixes both levels — the
> window geometry and the container allocation — exactly as the spec
> directs, and retires the last baked-in visual defect (the hero
> artwork's rectangular boundary).

## The window (spec §2)

| Behaviour | V0.6.82 | V0.6.83 |
|---|---|---|
| first-run target | 1536×1024 composition @ ~92% of the work area | **1440×900** wherever the work area comfortably supports it (§2.1); the ~92% rule stays for smaller work areas |
| window minimum | 760×440 (static) | **screen-derived**: the 1100×720 band wherever supported, ~96% of the work area below that, 760×440 absolute floor (§2.2) |
| tiny saved geometries | a deliberate hand-resize persisted forever | **clamped up** to the useful minimum — "never keep restoring an accidentally tiny geometry" (§2.1, `min_wh` in `sanitize_restore_plan`) |

`utils/geometry.py` owns every decision (pure, unit-tested):
`target_default_size`, `minimum_window_size`, and the extended
`sanitize_restore_plan`. Measured on the dev rig (1920×1080 work area):
fresh launch opens at **exactly 1440×900 centered**, 3 columns, no
scrollbar. On 1366×768-class work areas the fresh default is 1257×706
(the spec's "use most of the work area; retain a 2-column grid" row);
on 1024×600 the minimum scales to 983×576 — never above the work area.

## The rail (spec §3.1)

`clamp(180, 0.18 × window_width, 260)` logical px, applied from
`ElixirWindow.resizeEvent` → `Sidebar.set_rail_width` (the parent owns
the rule; the rail applies it — Qt layout propagation, never absolute
positioning). Below 232 px the rail switches to a compact profile:
tighter brand row (36 px leaf, 24 px wordmark) and nav labels that
**word-wrap to two lines** — full text at legible sizes, never clipped,
never shrunk (spec §3.1's explicit prohibition).

| Window | Rail | Share |
|---|---:|---:|
| 1440 | 259 | 18.0% |
| 1280 | 230 | 18.0% |
| 1100 | 198 | 18.0% |
| 1000 | 180 | 18.0% |
| 2000+ | 260 (ceiling) | ≤16% |

## The hero (spec §5/§6)

- **The artwork is now a TRUE transparent RGBA composite.** The
  V0.6.78–82 "flatten onto `bg_hero`" step is retired — it baked an
  opaque rectangle that occluded the card's painted decoration (the
  exact "visible rectangular boundary" the audit flags). The §5.2
  validation confirms the asset's background pixels are genuinely
  transparent (alpha 0, feathered edges; verified over light AND dark
  checkerboards + both themes) — the books/quill/inkwell now composite
  directly over the painted surface in both themes.
- **The height is body-driven**: ~0.325 of the scroll viewport
  (§6: "approximately 220–250 px, adapting gently"), clamped [240, 336].
  At 1440×900 the hero lands ≈254 with **no vertical scrollbar** and all
  three grid rows visible; the reference window gets ≈289 — the audit's
  "reduce its relative height" vs the reference's ~0.38 share.
- **The whole text rhythm scales** with the hero target (the V0.6.82
  ink-calibrated 336 px reference rhythm × s): the rhythm spacers became
  scaleable `QSpacerItem`s, the CTA's QSS padding tracks s (44 px touch
  floor), and the art budget respects the text column's MEASURED need
  first — the still-life yields before the pinned two-line breaks ever
  wrap (§5.3 layering, text protected).
- Header 68→50 and status strip 56→42 (§3.3/§6 bands: 44–52 / 38–44).

## The Quick Tools reflow (spec §4)

Tiered above the V0.6.81 measured safety net:

- **3 columns** only while a third of the grid still gives every card
  its **single-line title** (the measured comfort width: the widest
  title on the RUNNING font stack + the tightened card chrome
  24/14/18/14, gap 18);
- **2 columns** down to the readability floor (272 px cards: wrapped
  2-line titles, wrapped descriptions — never a clip, titles
  word-wrap);
- **1 column** only when even two floor-width cards cannot fit.

| Window | Columns | Cards/row width |
|---|---:|---:|
| 1440×900 | **3** | 353 (single-line titles) |
| 1280×800 | 2 | 471 |
| 1100×760 | 2 | 397 |
| 893-class (small screens) | 2 | ~302 |

At the primary acceptance target (1440×900): 3 columns, 9 cards in the
reference order, the featured dark-green Full Conversion Wizard ninth
card, **no scrollbar**, hero→tools gap 28 (§6 band 24–32).
