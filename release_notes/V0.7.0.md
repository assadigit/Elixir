## What you'll notice first

1. **The 10 progress dots are gone.** In their place: five named stage
   chips — **SOURCE · OUTPUTS · MODELS · TUNING · REVIEW** — each with a
   small segmented track (one segment per step in that stage). Finished
   steps fill in with a check mark, the step you're on gets a soft
   emphasis ring, and its stage label lights up in the accent color.
   Hovering a stage lists its steps; below 780px window width the small
   sub-captions politely step out of the way.
2. **Every step opens the same way:** a numbered amber badge, a plain
   title, and a one-line caption ("Pick the file, then choose how Elixir
   should read it — Auto suits most books."). One grammar across all 10
   steps, consistent 20px frame margins, and a nav bar with a proper
   40px+ click target on Cancel (left) and ‹ Back / Next › (right).
3. **Step 1 asks one clear question** — "How should I read this PDF?" —
   with three cards instead of six:
   - **Digital** — text-based PDF; charts and tables on text pages are
     *extracted*, not re-OCR'd (and this card now turns that extraction
     ON for you).
   - **Scanned** — every page is *read* by the vision-OCR engine. For
     scans and photos of text.
   - **Auto — RECOMMENDED** (the default): I detect which pages need
     OCR and read only those.
4. **The "Configuration profiles" box is gone** from Step 1 (nothing
   else used it), which — with three cards — means the whole step fits
   its window again (the audit's B10 overflow).

## The honest OCR mode (decision D3, closing bug B2)

**What you saw before:** the old "Full OCR" and "Infographics" presets
set a "force OCR on every page" flag that the backend honored **only
for academic papers** — on any other document it silently did nothing
(a fully-digital book under "Full OCR" got zero OCR). Six cards also
varied a handful of flags that were never read at all.

**What changed:**

- A new `ocr_mode` setting — **digital / scanned / auto** — carried from
  the card you pick, through the wizard state, onto the conversion
  request, and branched on in the extraction pipeline:
  - **digital** — page-scan detection OFF, figure-text + table
    extraction ON (the card's promise).
  - **scanned** — every page marked for the vision-OCR engine set, for
    any document type (this **supersedes** the academic-only force
    branch — that's the B2 fix).
  - **auto** — exactly the previous behavior, including the academic
    two-stage path.
- **Scanned mode's engine set is exclusive (decision D2):** your
  vision-capable summarisation model → the configured OCR model →
  OlmOCR → Qwen VL. **Tesseract, PaddleOCR, and the local-VLM fallback
  are excluded** — never constructed, never called. If the vision
  cascade has nothing available, the page fails honestly with a clear
  message instead of quietly degrading to a worse engine.
- **The old flag is a deprecated alias for one release:** any saved
  "force OCR on every page" choice now maps to scanned mode (for any
  document type — the bug fixed); it will be purged next release.
- **Dead flags purged in the same pass** (the audit's dead-code
  register): the "auto-detect scanned" flag (log-only — detection always
  ran), the preset `content_filter.min_*` values (the filter hardcodes
  its thresholds and never read them), and `is_academic` from the wizard
  data dict (the converter re-derives it). The wizard and the Settings →
  Presets page now apply presets through **one** shared applier speaking
  the same `ocr.mode` vocabulary — the previous split-brain (wizard
  applied a subset, Settings applied everything) is gone.
- The Settings → OCR page follows: the dead auto-detect checkbox and
  the legacy force toggle are replaced by the same 3-mode switch, and
  the Review step + the conversion log now show the OCR mode you're
  actually running.
