# V0.6.4 — the user-reported Summarizer Tool backlog: multi-format outputs · the custom title · the black output theme · the Farsi fix · the fine-tuned depth prompts · "Quality"→"Depth"

Six items, all reported against the standalone Summarizer Tool. 35 of the 56 new tests fail on the pre-fix HEAD (git-stash-verified). All fixes content-agnostic.

## The six

- **1. Multi-format outputs** — a checkbox row (Md / docx / PDF) replaces the single-choice dropdown: every checked format gets its own file from one run.
- **2. Custom title** — a toggle-hidden input (the user's example: "BMW Company History") replaces the auto "pasted — standard summary"; the title lands in the front-matter / docx Title / pdf H1.
- **3. Black output theme** — the docx headings (Word's blue template) and the pdf CSS (a green theme) both go near-black, matching the app's dark UI.
- **4. The Farsi fix** — Farsi text came back summarized (and translated) in English. Root cause: the shared book-pipeline prompt with an EMPTY `{{language}}` variable — an all-English prompt dutifully producing English. The depth prompts now carry the explicit rule "Write in the same language as the text.", and the write side keeps the response VERBATIM (no XML re-assembly re-labeling sections in English — pinned with a Persian round-trip test).
- **5. The fine-tuned depth prompts** (`core/summarisation/tool_prompts.py`, new) — the user-supplied Fast/Standard/Thorough texts, adopted VERBATIM (only chat-mangled line breaks re-flowed). A code module, not a `prompts/` bank file — the V0.6.1 precedent: a versioned prompt contract pinned by tests that the always-overwrite re-sync can never silently change.
- **6. "Quality" → "Depth"** — the label, the auto-filenames, and the settings keys follow the user's terminology.
