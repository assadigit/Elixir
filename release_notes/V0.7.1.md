## What you'll notice first

1. **Step 2's page range is a real control now** (it used to be two
   tiny spinners in a quiet corner with no tooltips). The card carries
   15px labels, 32px spinboxes, and a **live feedback line** that
   updates as you type: "Pages 12-340 — 329 of 397 pages (~83%) will
   be processed." — or, when you've picked chapters, "All 397 pages.
   14 chapter(s) selected from the table of contents." An invalid
   range is told to your face: "'from' must be ≤ 'to'." "Process all
   pages" stays the default; unchecking it enables the range fields
   and disables chapter selection (a chapter can span outside a
   range) — the same rules as before, just visible.
2. **"Detect chapters from the table of contents" is a first-class
   action** instead of a small grey secondary button: a card with a
   proper list icon, the title, the honest caption **"Most accurate —
   reads the book's own outline."**, and a prominent primary button.
   The chapter-picker dialog behind it is unchanged (its 7 scored
   parsers were already solid) — this is promotion, not rework.
3. **Step 2 gained a "Segmentation" row that tells the truth.** The
   old "Page group size" spinner was a dead control — logged and
   ignored; nothing read it. It now reads: "Processing blocks: Auto —
   block size measured from this book (typically ≈ 8 pages)" with an
   advanced 4-25 override, and the honest caption "Blocks are used
   only when no chapter structure can be detected — pages are grouped
   into multi-page blocks, never arbitrary token slices."
4. **Step 3 asks one question instead of showing five checkboxes.**
   "◉ Automatic — recommended: I scan every page and OCR only the ones
   that need it, with the best available engine." / "○ Manual control"
   opens an advanced drawer with only the controls your Step-1 reading
   mode makes real — and an engine-set line that names the actual
   cascade (auto: "…→ Paddle (if enabled) → local VLM → Tesseract. The
   first engine that succeeds wins."; digital: "No page OCR — the
   PDF's own text layer is read…"; scanned: the locked D2 set with
   Tesseract/PaddleOCR/local-VLM explicitly excluded).
5. **The OCR timeout and the PaddleOCR toggle finally do something.**
   These two Step-3 controls were dropped on the floor between the
   wizard and the backend — only their Settings-dialog twins worked,
   and the backend clamped the timeout to ≥120s anyway, so the
   combo's "30/60/90" items were fiction. Both now travel: wizard →
   request → OCR service (which still enforces the 120-second floor),
   and the combo offers the honest 120/180/300 band.

## The page-group wiring (decision D5) — the invisible half of this release

**What you saw before:** "Page group size" sat on the conversion
request with a default of 10 and *zero readers in the entire backend*
(the audit's dead-code register). Whatever you set, the book was
chunked the same way.

**What changed:**

- **`page_group_size` is now the block size of a page-group chunking
  fallback** — a new `PageGroupSegmenter` in the AUTO cascade, sitting
  between the semantic attempt and the raw token chunker. When no
  chapters, TOC entries, or headings can be detected, the pages are
  grouped into N-page blocks (the cut pulled back to the last blank
  line, so a boundary never splits a paragraph) instead of arbitrary
  token slices.
- **Auto computes N from your book:** it measures the token density
  of the pages, targets ≈ 5,000 tokens per block (the plan's 4-6k
  band midpoint), and clamps to 4-25 pages — typically ≈ 8 pages for a
  normal book. A manual value (the 4-25 spin) overrides it.
- **A structural bug this uncovered (and fixed):** the heading
  segmenter *always* returns at least one segment — its trailing
  catch-all. So "no chapter structure" books were silently getting
  ONE giant segment spanning the whole book (the monster-segment
  map-reduce the code itself warns about). A single segment covering
  >60% of the book is now rejected as "no structure found" (the
  file's own monster-segment criterion, applied at acceptance), and
  the cascade falls through to semantic → page-groups → tokens.
  Without this gate the new stage could never have fired — it would
  have been the exact dead-code pattern this campaign exists to kill.
- **`chunk_by_page_groups` got its first real reader** (it rode the
  request unread since it was introduced); defaults unified to
  0 = Auto on all four surfaces (request, map row, settings,
  wizard state).

## Bug B3 closed — the two dead Step-3 controls

**The user report:** "the OCR timeout and PaddleOCR toggle in the
wizard never seemed to do anything."

**Root cause (audit §W5 / bug register B3):** `to_ui_data()` dropped
`ocr_timeout` and `use_paddleocr` — they were never in
`_REQUEST_FIELD_MAP`, so the wizard's values never reached the
conversion request. Only the Settings-dialog twins (writing straight
to settings.json) worked; the backend clamped the timeout to ≥120s
regardless, so the wizard combo's 30/60/90 items were fiction.

**The fix, both directions:** the request gains the fields, the map
carries them, the OCR service prefers the request over settings
(settings stays the fallback for request objects that predate the
fields), the wizard loads the saved values at open, `save_book_settings`
persists them so the regenerate path round-trips, and the queue path
carries them through the same rows. A saved sub-floor value (30s from
an old run) maps to the honest 120 floor.

## The OCR step rework (item 3d) — honest by mode

Step 1 owns the reading-mode axis (digital / scanned / auto — landed
in V0.7.0); Step 3 now *respects* it instead of showing controls that
would lie:

- **auto** — the full drawer: vision-model pass, figure & table text
  extraction, tables (camelot/tabula), PaddleOCR fallback, timeout.
- **digital** — no page-OCR controls (the text layer is read; charts
  and tables are *extracted*, not re-OCR'd).
- **scanned** — the engine set is locked by D2; the drawer shows the
  set as information, not toggles that would lie. Only the timeout
  remains (it is a latency, not a reading-mode value — it flows under
  both radio choices).

Choosing "Automatic" saves the honest defaults (vision on, Paddle
off, figure/table follow Step 1's cards); "Manual control" saves
exactly what the visible controls say. A control the mode makes
meaningless is never written over — a no-op, not a lie.

## The deprecated full-OCR alias is purged (the scheduled one-release cleanup)

V0.7.0 mapped the old "force OCR on every page" flag to
`ocr_mode="scanned"` for exactly one release (the compatibility
window). This release, one version later, removes it everywhere: the
request field, the map row, the settings default, the preset field
(dead — never read), the resolver branch, the Step-3 checkbox, the
review line, the queue entry, the start-log line. A stray attribute
from a V0.7.0-era saved config no longer affects resolution and never
reaches the request. `ocr_mode` is the only reading axis.
