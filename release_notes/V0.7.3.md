# V0.7.3 — Step 5 stops lying about where your models come from, remembers your picks, and shows the REAL context/output limits (bug B6 closed)

> **What this is:** Phase ⑤ of the approved wizard rework
> (`ELIXIR_WIZARD_REWORK_ROUND_2_PLAN.md` — Step 5, work items
> 5a-5c). The V0.7.0-V0.7.2 releases rebuilt the wizard shell, Step
> 1's mode cards, Steps 2-3, and Step 4's category cards; this release
> reworks the models step — the one that decides which local AI model
> does the work and with what limits — and closes the audit's B6.

## What you'll notice first

1. **Picking "LM Studio" now actually asks LM Studio.** Before this
   release, the model dropdown silently listed *Ollama's* models no
   matter which backend you picked — the LM Studio URL was never used
   for discovery (audit B6, `step5_models.py:413-427,452-458`). Each
   backend is now asked on its own server: Ollama via `/api/tags`, LM
   Studio via its own `/v1/models`, llama.cpp via the server's model
   listing. The "No models found" hint names the server that was
   actually asked (the old copy said "Ollama" for everyone).
2. **The wizard remembers your model picks.** The summarisation and
   OCR combos open on what you last used instead of an empty box, a
   refresh keeps your pick selected while the server still lists it,
   and a pick the server no longer lists stays selectable (a
   temporarily-down server must not forget your choice). A successful
   run re-confirms the picks in settings — "manual picking,
   auto-remembered" (D14). No auto-picking was added: you choose, it
   remembers.
3. **One place for the limits, and it tells the truth.** Step 5 keeps
   the ONLY "Model context / Model output" inputs. Step 7b's duplicate
   "Summarization limits" group — whose save order silently overwrote
   Step 5's values at Start (audit §W12) — is deleted. The
   summary-cache checkbox that lived in it moved into Quality
   controls, beside Resume mode.
4. **The new honest line.** Under the inputs:
   **"Effective after model limits: 32,768 ctx / 16,000 out."** The
   backend always clamped your numbers (VRAM ladder, the 32,768
   context floor, output 2,048 in compact mode / 8,192 for small and
   low-bit models / 16,000 for large ones) — now the wizard shows what
   will actually run. A new **"Auto — let the model class decide"**
   checkbox (on by default) disables the spins and lets the model you
   picked dictate both numbers; uncheck it to set them yourself, and
   the line keeps telling the truth either way. Switching the model
   updates it live (a 27B model shows 16,000 out; a 12B shows 8,192).
5. **The defaults finally agree.** The audit's defaults-disagreement
   table (state vs settings vs request: coverage 85/50/0.50, context
   32768/16000/131072, output 8192/4096/4096) is resolved — one
   default per field, one owner: **coverage 85 everywhere**, context
   **32,768** everywhere, output **16,000** everywhere.

## A bonus bug found and fixed while pinning the defaults

While verifying the unified defaults end to end, this session found a
live defect in the settings layer: the secret-path heuristic treated
any path containing "token" as a *credential* — and in this app
"token" means LLM tokens. Four numeric/boolean fields
(`max_context_tokens`, `max_output_tokens`, `token_limit`,
`token_saver`) were being resolved through the OS-keychain branch:
their request defaults came back as strings, and on machines with a
keyring a plaintext numeric setting could be "migrated" into the
keychain and wiped from settings.json. The heuristic now matches only
auth-token compounds; every real credential path (the api_key family)
is untouched and covered by pins.

## The mirror — why the line can't lie

The new `core/summarisation/effective_limits.py` is the single source
both sides share: Step 5's line renders from it, and the Summarizer's
own VRAM ladder (`_auto_detect_context_limit`) now delegates to it —
one ladder, no drift. Pin tests construct REAL Summarizers and assert
the mirror predicts the live ladder's result exactly, for every model
class and both context routes. The line's tooltip also admits what it
doesn't simulate: a known model can raise context further at start
time (the model registry).
