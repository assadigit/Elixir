# V0.6.59 — "I already downloaded whisper large v3 from handy computer, so I just select the gguf model" — the GGUF catalog: the app now READS the model file's own header (a real GGUF metadata parser, verified against handy-computer's actual large-v3 file), a "GGUF model" dropdown lists every Whisper .gguf on disk (exe folder, C:\transcribe.cpp\models, the saved model's folder, ~/Downloads — where the browser download lands), the engine VERIFIES the selected file before the CLI launches (wrong-architecture / legacy .bin mistakes fail in seconds with the fix, not minutes into the run), and a missing model triggers a self-healing disk scan — 76 new pins / 327 P affected sweep / 0 regressions

## The user request

> "Look I alreayd downloaded whisper large v3 from handy computer,
> can you make the backend for it yourself, so i just select the
> ggql modekl."

The GGUF is on disk. What the app lacked was the backend that makes
"just select the file" actually WORK:

1. **The engine trusted the setting blindly.** A stale path, a llama
   GGUF picked by mistake, or a legacy `ggml-*.bin` all surfaced only
   as a CLI crash minutes into a run. Nothing ever LOOKED inside the
   file.
2. **A missing model fell back to one hardcoded path.** A downloaded
   model sitting in Downloads or `C:\transcribe.cpp\models` (under a
   different quant name) was invisible to the app.
3. **The dialog's only affordance was a raw file browse** — with a
   filter that even offered `*.pt` files the CLI cannot load.

## What was verified live this session (evidence-first)

- **handy-computer's Hugging Face model list** (the org the operator
  named): `handy-computer/whisper-large-v3-gguf` ships exactly
  `whisper-large-v3-{F16,Q4_K_M,Q5_K_M,Q6_K,Q8_0}.gguf` (plus tiny /
  base / small / medium / large / large-v2 / large-v3-turbo and `.en`
  repos). The filename parser targets these REAL names.
- **The actual file header**: `whisper-large-v3-Q5_K_M.gguf` was
  range-requested and the metadata walked by hand AND by the new
  parser: `general.architecture = 'whisper'`,
  `general.name = 'Whisper Large v3'`,
  `general.size_label = '1.5B'`, 68 KVs, GGUF v3, 1261 tensors, and
  tokenizer-scale arrays (`tokenizer.ggml.tokens` x51,866 — which the
  reader now skips with a summary marker instead of materializing:
  the fresh-eyes review measured a crafted 2M-item array at ~550 ms
  of UI-thread CPU; the real file parses in ~55 ms, bounded).

## The fix — the GGUF catalog (three pieces)

1. **`core/transcribe/model_catalog.py` (new, Qt-free stdlib leaf):**
   a REAL GGUF header reader (magic + version + tensor count + all 13
   metadata value types, string arrays walked, byte-capped at 4 MB so
   a 3 GB model is never slurped and a corrupt count field can never
   hang the read); a filename parser for handy-computer's naming
   (`whisper-large-v3-turbo-Q5_K_M.gguf` → family large-v3-turbo /
   quant Q5_K_M, legacy `ggml-*.bin` flagged); a directory scanner
   (exe dir + `exe/models`, the saved model's folder,
   `C:\transcribe.cpp\models`, `~/Downloads`; non-whisper GGUFs
   EXCLUDED, legacy `.bin` included but ranked last and never
   auto-picked); and `resolve_model()` — the engine's single decision
   point.
2. **The engine (`transcribe_with_cpp`):** the old
   trust-the-setting-block is gone. The selected GGUF is VERIFIED
   from its own header BEFORE the CLI launches — a llama GGUF fails
   in seconds naming `general.architecture = "llama"`, a legacy
   `.bin` fails with "transcribe-cli.exe loads .gguf", a missing
   model triggers the scan (auto-picks the best Whisper GGUF, logs
   `[MODEL-SCAN]` lines, and persists the pick back to settings —
   self-healing). The `[MODEL]` log line now carries what the file
   itself PROVED: `  [MODEL] whisper-large-v3-Q8_0.gguf (1.6 GB) -
   Whisper Large v3 · Q8_0 · 1.5B · GGUF header verified
   (architecture: whisper) - the model file reloads on every run`.
   Unparsable headers proceed honestly unverified (a `[WARN]` line;
   the CLI is the final authority).
3. **The dialog:** a "GGUF model" row for the transcribe.cpp engine —
   a combo listing every discovered Whisper .gguf (display:
   `Whisper Large v3 · Q8_0 · 1.6 GB · header-verified`) with the
   saved setting pre-selected, a 🔄 rescan button, and the 📁 Model
   browse button (moved into the row; its filter now puts `*.gguf`
   first — the old filter offered `*.pt`). Selecting from the combo
   saves the setting in one click — the "just select the gguf model"
   flow. The run header now names the selected GGUF for cpp runs
   (the V0.6.57 gap: they logged no model line at all), and the
   faster-whisper row's dangling label is finally hidden with its
   widgets.

## The fresh-eyes review (Task 15, pre-release)

Verdict: **RELEASE READY**. Its 5 SHOULD-FIX findings were fixed
BEFORE this release, each with a pin: (1) an unguarded
`Path(current)` at dialog open (the V0.6.53/55 construction-crash
class) — settings values are now str-coerced; (2) the pathological
UI-thread freeze — arrays beyond 1,000 items are skipped with a
summary marker; (3) the scan could auto-pick + persist a legacy
`ggml-*.bin` unvalidated — the auto-pick gate now requires the GGUF
magic, and only-`.bin` discoveries get a dedicated error naming them;
(4) the overpromising "the engine will verify it" log line — the
verdict now states what the header actually proved; (5) weak test
pins (a tautology, an `A and B or C` precedence bug, a 300 MB
fixture) — tightened.
