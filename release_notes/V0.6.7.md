# V0.6.7 — the approved backlog: dead code deleted, one vision-classification truth, proxy-safe provider transports, the save block finally tested — 83 new tests

The second release from the Agentic Review/Refactor/Test Loop charter: the operator approved the previous session's backlog (delete the provably-dead modules; fix the vision-keyword drift, the provider transports, the untested save block, and the zero-coverage modules "if safe"), and each item was safety-assessed before touching it. One theme: **one truth per fact, and the untested parts get their safety nets.**

## 1. Dead code deleted — with the proof cited

Two modules and nine properties shipped zero references anywhere (verified at deletion time: no imports, no bare/nested/`getattr`/`hasattr`/dynamic access, no `__init__` re-exports — every grep hit was a docstring inside the dead module itself):

- `core/pipeline/output_time_estimates.py` — the V7.6/V7.7 tier-label framework nothing ever imported.
- `core/models/config_views.py` + the 9 `ConversionRequest` view properties (`ocr`/`postprocess`/`segmentation`/`summarization`/`outputs`/`quality`/`advanced`/`selection`/`docx_config`) — the V10.21 grouped-access adapter that no caller ever used. The flat fields (used by 500+ call sites) are untouched.

Nothing user-visible changes; deleting unreachable code by construction cannot. One dangling docstring citation in `core/outputs/registry.py` was updated to stop referencing the deleted module.

## 2. The vision-model keyword list — five copies, three drifted variants, now one

The "is this a vision model?" heuristic had been copy-pasted into 5 places that drifted into 3 different lists. The user-visible symptom: `minicpm-v` was offered by the OCR dialog as an OCR model but classified **text** by the dependency checker and badged 📝 in the model pickers. `model_taxonomy.py` — the declared single source of truth for model classification — now carries `VISION_MODEL_KEYWORDS` (the union of all three variants, nothing lost, verified programmatically) and `is_vision_model()`, and all five sites read it (the OCR dialog references the SSOT object itself, so it can never drift again — pinned by an identity test).

Per-site behavior changes, all in the more-complete direction, documented at the SSOT:

- **Dependency checker, About dialog, model-picker badges** gain minicpm/moondream/mmproj/multimodal/bonsai/fuyu/kosmos/florence detection — the `minicpm-v` misclassification is fixed.
- **The OCR dialog** gains olmo/mmproj/multimodal/bonsai.
- **The llama.cpp vision gate** gains the ocr/minicpm/moondream/fuyu/kosmos/florence families it previously missed — a `minicpm-v` served by llama-server no longer silently degrades scanned pages to the Tesseract path. A keyword false positive there is fail-soft: the OCR service falls through to the Qwen/Paddle/Tesseract engines, and the capability probe is cached once per conversion.

**Caveat kept, flagged:** `olmo` also matches text-only OLMo-family tags. It has classified olmo tags as vision on the display tier for years; removing it would be a behavior change in the other direction and needs rig evidence, so it stays — documented at the SSOT for the next person.

## 3. The four provider transports — everything goes through the one routing rule

Four LLM call sites still used bare `requests.post` (new TCP session per call, and — the real hazard — `trust_env=True` always, so a misconfigured `HTTP_PROXY` broke **localhost** FreeLLMAPI/Ollama calls). `openai_compat_provider.complete`, `claude_provider.complete`, and the two Ollama vision methods (`supports_vision` `/api/show`, `complete_with_image` `/api/generate`) now route through `session_for_url`: localhost endpoints get the proxy-immune pooled session, cloud endpoints keep env-proxy behavior, everything gains connection pooling. The OpenAI-compat response parse also switched from the hard `choices[0].message.content` deep-index to the shared shape-safe `extract_openai_content` — same migration as the V18.20.4.11 dispatcher: a malformed 200 body now flows into the same retry path as an empty response instead of raising straight to None.

Scope notes (deliberate): the OpenAI Batch API path (openai.com-only — proxy behavior identical either way) keeps its transport; a fifth bare `requests.get` in the translation dialog's model refresh is recorded in the findings file for a future pass.

The two Ollama vision methods had **zero tests** — they now have a first characterization battery (mmproj/adapter detection, image payload, fail-safe paths, seam routing).

## 4. The incremental-save block — extracted verbatim, then tested

The per-chapter save block at the heart of `run_summarization` (184 lines inside the 1,202-LOC function) had never executed under test: failed-summary skipping, run-stamped filenames, the write-once `<!-- COMPLETE -->` adoption, the verification-layer plumbing, the disk-full error. It now lives at module level (`_save_chapter_summaries_write_once`), moved **verbatim** — the move was verified mechanically: all 8 statements AST-identical to the original block, the nested helper byte-identical, and the first extraction attempt was automatically refused when the purity check failed (the guard works). 14 tests pin the contract: a completed chapter is never rewritten, a crashed/incomplete file is, legacy unstamped results keep their exact filenames, errno-28 raises the actionable "Disk is full — resume will skip completed chapters" error, the verification layer is fail-open. The rest of the god-function decomposition remains deliberately out of scope.

## 5. Four zero-coverage live modules, characterized

- `utils/dependencies.py` — the checker's cache TTL, the server probe, `check_all`'s full shape (with the SSOT vision split), `model_exists`.
- `core/pipeline/profiles.py` — the wizard's named settings: sanitize, save/list/load/delete roundtrip, corrupt-file skip. (Tests redirect the profile dir to a temp folder; the suite-wide "tests write the real `~/.elixir`" question remains an open operator decision.)
- `core/pipeline/multi_pdf_merge.py` — merge happy path, missing-dir skip, no-summaries → None, first-file-wins.
- `core/outputs/podcast_coverage.py` — the ≥90% coverage gate's phrase extraction, thresholds, verify, and revise paths. Characterization surfaced **two real blind spots** (pinned as documented limitations, not fixed — that changes gate semantics): the quoted-phrase rule only matches double quotes and words under 4 characters never join phrases, so a keypoint about `'end game'` is judged on its other words alone; and the top-5-phrase cap can crowd a short quoted phrase out entirely.
