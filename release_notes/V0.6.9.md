# V0.6.9 — the green-baseline release: both operator DECISIONS landed (VRAM enforcement restored, parenthetical grounding tightened), the suite green for the first time

The fix-session's two queued operator decisions are answered and landed, and with
them the last 14 documented failures close: **7,548 passed / 0 failed / 43 skipped
/ 16 deselected** — the first honestly-green full-suite baseline in the project's
history (V0.6.7's audit had retired the "14 pinned environment failures" myth; this
release retires the failures themselves). Rule 3 (net-green) is meaningful again:
from here on, any red is a regression, full stop.

## 1. DECISION 1 — the VRAM overbudget enforcement is RESTORED

The V0.5.14 hotfix (`a0b711c`) had made `Converter._enforce_vram_budget`
NON-BLOCKING: an unconditional `return None` ahead of the policy block, plus an
nvidia-smi informational probe — silencing `local.vram_overbudget_policy` for every
non-interactive start path (queue / service dialogs / scripted runs) while the
setting, its schema comment, the request field and the docstring all still promised
enforcement (the V0.6.7 audit's BLOCKER; 12 red characterization tests at HEAD).

The operator chose **Option A (restore)** with this cost model: *an estimator error
(a special-quant 27B estimated at 12.9 GB vs 7.6 GB actual) costs ONE "Proceed
anyway" click in the wizard — the button already exists and stamps
`request.vram_overbudget_acknowledged`; a genuine overbudget is stopped BEFORE any
work is done.* The V18.20.4.10 policy block now runs again, byte-identical to its
original form (verified by the review-2 diff against `a0b711c~1`): `proceed` →
WARNING + continue; `abort` → fail fast; `ask` (default) → fail fast unless the
wizard stamped the acknowledgment. The hotfix's inserted block (probe + unconditional
proceed) is removed wholesale; the older V0.5.13 belt-and-suspenders escapes were
deliberately NOT reinstated — the wizard click and the global `proceed` are the only
escapes. `scripts/repeatability_run.py` keeps its explicit `policy=proceed`
(scripted runs cannot ask). The 12 previously-red tests pass **unchanged** — they
pin the original contract verbatim.

## 2. DECISION 2 — the parenthetical-promotion grounding is TIGHTENED

The V0.5.15 "regex-grounded exemption" (`postchecks/field_phases.py`) kept any
bullet whose claimed author was merely IN the `extract_citations` roster — but a
parenthetical-only cited author ("… (Khan 1983) …") lands in that roster BY
CONSTRUCTION, so the exemption defeated exactly the misattribution drop the
V18.20.3.2 parenthetical-promotion veto enforces (the audit's documented contract
conflict; 2 red tests).

The operator chose **Option A (tighten)**: *an author counts as "grounded" only
when an attribution verb is actually held somewhere (or within the detector's
matching range) — a pure citation-list name no longer counts as grounding; this
preserves correctly attributed authors as a fallback and stays effective against
genuine attribution errors.* `_v0515_grounded` (roster membership alone) becomes
`_v069_grounded` = roster membership AND `_name_holds_any_attrib_verb(claimed,
source_text)`. The detector's own escape (a) still never confirms a promotion for
an author who holds a verb in a surname-matching span, so correctly attributed
authors are safe twice over; the tightened exemption additionally rescues the one
reachable outside-the-range shape (a passive-agent hold whose 80-char look-back
window the detector's per-span scan clips — pinned end-to-end by a dedicated
corridor test). This also restores parity with the generation-time veto
(`gap_fill_batch`), which never had the exemption: the two layers of the same veto
no longer disagree.

## 3. review-2 — the fresh-eyes pass over both decisions (3 residuals, all fixed)

A read-only reviewer verified both commits sound (byte-identical restore, honest
tests, no test-cheating, no caller left depending on never-abort) and found three
SHOULD-FIX residuals, all fixed in this release:

   extracted `_v069_recoverable_sentence` helper (roster AND verb-held-somewhere);
   the thorough layer and the veto now agree in both directions.
2. **README placebo rows removed** — the "Non-blocking overbudget (V0.5.14)" row
   (false since the restore) and both `summarisation.model_vram_override_gb` rows:
   the override has ZERO runtime read sites at HEAD (the V0.5.14 hotfix deleted the
   last reader; it was never registered in the settings schema). Restoring the
   V0.5.13 override read is FLAGGED for the operator as a possible future escape
   hatch for special-quant owners (beyond the one-click proceed) — not done without

3. **Doc accuracy** — `models.py`/`errors.py` no longer claim `VramOverbudgetError`
