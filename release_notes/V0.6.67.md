# V0.6.67 — root cause found and fixed: a hidden line of test code was running your app on an invisible "offscreen" screen — since V0.6.63, every launch started the app perfectly but it could physically never show a window. That line now only runs during the automated self-test. Plus: windows can never get stranded off-screen, and the automated install test now demands a genuinely visible window

## The report this ships

> "Installed new version, but still didn't run, however this time we
> have diagnostics" — **with the diagnostics zip attached.**

Thank you — that zip ended the guessing. The V0.6.66
**Elixir - Collect Diagnostics** tool did exactly what it was built
for: it turned "still doesn't open" into evidence, and the evidence
has a verdict.

## The verdict (in plain words)

**Your diagnostics proved the app was running the whole time** — every
launch in your logs completed startup perfectly, and at the moment you
collected diagnostics the first launch of the session was still alive
and healthy. No crash, no hang, no missing files, no antivirus
problem, nothing wrong with your machine.

That evidence pointed at "the window exists but you can't see it", and
the investigation closed the ring: **a line of test-harness code set
Qt's "offscreen" rendering mode** — and because the launcher imports
that test module on every start, **every launch since V0.6.63 ran the
whole app on an invisible offscreen surface.** The app worked,
logged, even answered "bring me forward" requests — to an offscreen
window no monitor could ever display. On any machine. Since the very
first installer release you tried.

The final unmasking happened on the build server: this release also
upgraded the automated launch test from "a window exists" to "the
window is visible and actually on a screen" — and the test immediately
refused to pass the offscreen window it had been rubber-stamping since
V0.6.63. That's what turned the bug from invisible to obvious.

Why each double-click looked completely dead:

1. **The first double-click** started Elixir — rendering offscreen.
   The app was healthy; its window simply did not exist on your
   desktop.
2. **Every later double-click** saw "Elixir is already running", told
   that instance to come forward, and exited. It "came forward" — on
   the offscreen surface. To you: nothing, every time.
3. There was no error, no crash log — because nothing ever failed.

## What's fixed

- **THE root cause:** the offscreen test mode now activates ONLY
  during the automated self-test (`Elixir.exe --selftest`), never on a
  normal launch. Your launches run on the real Windows Qt platform
  again. Guarded by automated tests so it can never silently return.
- **The window can no longer hide.** After the window opens, Elixir
  now checks its actual on-screen position; if any part of the window
  isn't on a real monitor, it's moved to the middle of your main
  screen automatically. This check also runs when a second launch
  asks the first to come forward — so an already-running invisible
  window heals itself the moment you click again.
- **Maximized windows are now checked too.** A window that was
  maximized on a second monitor (later unplugged) used to bypass the
  safety check entirely — that path is closed.
- **The window position file can't poison future launches anymore.**
  Positions saved while minimized (a Windows quirk that stores
  −32000 coordinates) or while maximized on a now-gone monitor are
  no longer written; the fallback is always "center of your main
  screen".
- **Double-clicking is now reliable:** if a running instance can't
  put a visible window on your screen, the new launch takes over and
  shows its own window instead of deferring to the invisible one.
- **Better startup evidence:** the startup log now records exactly
  where the window landed ("window shown — frame=… screens=…") and
  whether the app ever exited its event loop — so any future report
  is one glance, not forensics.
- **The gpu_probe log mystery explained and fixed:** every entry used
  to end after three header lines (torch isn't bundled in the Windows
  build and the write quietly died on that). It now says so plainly.
- **The CI launch test learned its lesson:** "a window exists" is no
  longer good enough — the automated test now requires the window to
  be **visible and actually on a screen**, so this entire bug class
  can never pass as green again.
- **Collect Diagnostics got sharper:** it now also gathers your
  saved window position, the monitor inventory, and the display
  scaling — the exact evidence this report was missing — and every
  step leaves a file even when PowerShell is blocked (your zip was
  missing the antivirus files for that reason; there's now a trace
  saying so).

## What to expect when you install

Install **Elixir-Setup-0.6.67.exe** over your current install (the
installer closes any running Elixir first — that's expected) and
double-click Elixir. **The window will open.** On a first run it
appears centered on your main screen; after you move or resize it,
the position is remembered (and sanity-checked every launch).

If anything is still off, run **Elixir - Collect Diagnostics** from
the Start menu and attach the zip — with the new geometry + screen
evidence, the next verdict will take minutes, not days.
