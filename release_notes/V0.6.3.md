# V0.6.3 — the user-reported modal button clipping: every message box now guarantees its buttons full label width

From a user screenshot: "Make sure all modals have enough space — 'Open file location' is truncated." The success modal showed "📂 Open File Locatio…" and "🔄 Try Anothe…".

## Root cause (reproduced with the shipped QSS, light + dark, exact numbers)

The success modal — short message text + three QSS-padded buttons — renders **355px wide, 19px narrower than its own sizeHint (374px)**: "📂 Open File Location" gets 132px where its sizeHint needs 142px. QMessageBox's internal post-show sizing can settle BELOW sizeHint when the text label is narrow; the button row then receives less than the buttons' sizeHints and QPushButton clips. The narrow-text case is exactly the common success path.

## The fix

**Per-button minimum widths** (`ui_qt/components/modal_button_fit.py`, new): raising each button's `minimumWidth` to its own `sizeHint().width()` propagates up the layout chain (button minimum → QDialogButtonBox minimum → dialog geometry), so the dialog can never render narrower than its button row.

A dialog-LEVEL `setMinimumWidth` floor was tried first and **rejected on live evidence**: layout activation during `show()` overwrites the widget minimum with the layout's `totalMinimumSize`, silently undoing the programmatic floor. Working WITH the layout chain instead of fighting it is the whole trick — and the rejection is pinned by a test (`test_dialog_level_floor_is_ineffective`) so nobody re-attempts it.

## The numbers

- 17 new tests, **15 fail on the pre-fix HEAD** (the 2 passing are Qt-behavior characterizations explaining WHY the fix is shaped this way). Pure geometry — content-agnostic.
- ruff clean; net-green.
